# Artifact provenance

What built this image, against the kit's rules 8 and 9 (`vendor/track1-coding-public/README.md`, "Competition rules") and the toolkit's Track 1 pack (`starter-packs/track1/AGENTS.md`: no model weights of any kind; non-LLM artifacts are ordinary bundled artifacts). The kit's code is under its `LICENSE` and the units under `DATA-LICENSE.md` (CC BY-NC 4.0). The build argument `AGENT` chooses the agent the verb runs, and the label `agenthon.agent` records it.

- Base: `finance-bench-sandbox:latest`, built on the desk from the kit's `docker/sandbox.Dockerfile` at `84049db` (`docs/dry-day.md` step 1 records the digest it resolved and its packages).
- `solve`: a two-line shell wrapper on PATH, written at build time: `exec python3 -m <agent>.solve solve "$@"` for `AGENT=n0`, `n1`, `n2`, `n3`, `n4`, `n5`, `n6`, `n7`, `n8`, `n9`, `n10`, `n11`, `l1`, `w1`, `w2`, `recall` and `pi`, `exec python3 -m examples.exemplar_agent.solve solve "$@"` for `AGENT=exemplar`. Each agent is a stage of its own in `agent/Dockerfile`, so an image holds its own agent's files and no other's, in any layer, but `AGENT=n11`'s, which holds `n0/` too: its last resort is N0's own request, by import.
- `n0/` (`AGENT=n0`), `common/` and `model.py`: our own code, written for this program. N0 is the naive one-call agent: it reads the mounted unit at run time (the instruction with its canary lines removed, a digest of the data files built by code, the instruction's paths mapped to the mounted files by the unit's own `environment/Dockerfile`), asks the House model once for a complete Python script, runs it, and on a failure asks once for a repair, at most 3 requests a unit. `common/` is the code it shares with later agents (the digest, the path map, the runner, the guard that removes any output file carrying one of the unit's canaries); `model.py` is the program's House client (`src/agenthon_t1/model.py`, standard library only). None of it holds a unit's id, text, data or answer, branches on a unit, or carries a solution written in advance: every deliverable is written by the script the House writes in that run (rules 8 and 9).
- `n1/` (`AGENT=n1`), with `common/` and `model.py` as above: our own code, written for this program. N1 is N0 fitted under the House's 4,000-token output cap, with three changes: its system prompt also asks for a compact script (no comments, docstrings or type hints, the whole script under about 200 lines); a reply the cap cut is continued up to twice, where N0 continues it once; and a script still cut after that runs as its longest prefix of whole lines that compiles, before any repair. At most 5 requests a unit. It holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by the script, or the part of it, the House writes in that run (rules 8 and 9).
- `n2/` (`AGENT=n2`), with `common/` and `model.py` as above: our own code, written for this program. N2 is N0 with one change: each of its requests asks the House model to think at low effort (the `low_effort` option of the model's chat template, which the House route passes through) where N0's asks thinking off; its prompts, its 3-request cap, its repair and its continuation are N0's. It holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by the script the House writes in that run (rules 8 and 9).
- `n6/` (`AGENT=n6`), with `common/` and `model.py` as above: our own code, written for this program. N6 is N2 with one change: each of its requests asks the House model to think under a budget of 100 reasoning tokens (the `reasoning_budget` option of the model's chat template, which the House route enforces) where N2's asks `low_effort`; its prompts, its 3-request cap, its repair and its continuation are N2's, which are N0's, and its log gives each reply's reasoning tokens. It holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by the script the House writes in that run (rules 8 and 9).
- `n7/` (`AGENT=n7`), with `common/` and `model.py` as above: our own code, written for this program. N7 is N0 with four changes for the House's 4,000-token output cap: its first request also says that a script too long for one reply may come in parts, each ending after a whole function, class or statement with a marker line, and each later part is asked for; a reply the cap cut keeps its longest prefix that compiles, and one request asks for the rest from the statement after it; a repair asks for only the functions, classes or statements that change, which code puts into the failed script by name (a whole script in reply is taken whole, and a splice that does not compile falls back to asking for the whole corrected script); and at most 12 requests a unit, where N0's is 3. Its system prompt is N0's. The added sentences are general, the same for every unit; N7 holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by the script the House writes in that run, joined or spliced by code from the House's own replies (rules 8 and 9).
- `n8/` (`AGENT=n8`), with `common/` and `model.py` as above: our own code, written for this program. N8 is N0 with its first request unchanged and four changes for the House's 4,000-token output cap: a reply the cap cut keeps its longest prefix that compiles, and one request asks for the rest of the script to its end, the lines that run it included; a script that defines functions and runs none of them gets the two lines that call its `main` (or its one function taking no arguments, defined last) added by code, and where it names no such function one short request asks for the lines that run it; a long failed script's repair asks for only the functions its error's traceback names, which code puts into the script by name (a reply the cap cut is asked again once, and the whole corrected script is the last resort); and at most 12 requests a unit, where N0's is 3, those beyond N0's own made only while the clock leaves the script the run time N0's first request promises it. Its system prompt is N0's. The added sentences are general, the same for every unit; N8 holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by the script the House writes in that run, joined or spliced by code from the House's own replies, and the lines code adds only call a function the House's script defines (rules 8 and 9).
- `n9/` and `qf/` (`AGENT=n9`), with `common/` and `model.py` as above: our own code, written for this program. N9 is N0 with one change: its system prompt gains one sentence saying that a module `qf` of vetted implementations of standard methods is importable and asking the script to call one where the task names its method rather than re-derive the formula, followed by the module's own one-line-per-function list (its docstring, read from the file at start). `qf/` is a general library, numpy and scipy only: textbook implementations of standard methods (Black-Scholes-Merton with forward-start, digital and single-barrier digital prices; Asian options by the geometric closed form and Levy's and Curran's approximations; first passage and running extrema of Brownian motion with drift; four copula log-densities and their Kendall's tau inversions; the moments of an Ornstein-Uhlenbeck process with jumps; implied volatility and its closed-form approximations; realized-variance noise and bipower measures; the Gaussian hidden Markov model's smoother and Baum-Welch fit), each function stating its formula, conventions and published source, every convention an explicit argument with no default. It holds no unit's id, text, data, parameter, expected value or answer, reads and writes no file, and is tested only against textbook values and identities (`tests/test_qf.py`); the House's script decides whether to call it and with what. N9's prompts, its 3-request cap, its repair and its continuation are N0's; it branches on no unit (rules 8 and 9).
- `n10/` (`AGENT=n10`), with `common/` and `model.py` as above: our own code, written for this program. N10 is N0 through its first run, its first request byte for byte N0's, with a second phase of its own: where the script fails (a non-zero exit, a traceback, a stop at its time limit, or exit 0 with no file written), a request under a repair system prompt of its own shows the task, the script as it stands, the exception and the traceback's lines inside the script, the end of what the run printed and the files it wrote, and asks for edits alone, each a few lines of the script quoted exactly and the lines that replace them (never the whole script). Code applies each edit where its quoted lines occur exactly once in the script, compiles the result (undoing one that does not compile), runs it again, and repeats while each run gets further (a different exception, a later line, more files, or a clean exit) and the clock leaves the run the seconds N0's first request promises it, ending after two rounds without progress; the run's printed output is kept to its last MiB a stream. At most 25 requests a unit, the House's allowance. Its prompts are general, the same for every unit; N10 holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by the script the House writes in that run, changed only by the House's own edits (rules 8 and 9).
- `n11/` and `qf/` (`AGENT=n11`), with `common/` and `model.py` as above: our own code, written for this program, and `n11/index.txt`, the index of `qf` that `scripts/qf_index.py` writes from `qf/`'s own docstrings in a build stage of its own (the script enters no layer of the image), and seventeen one-word files under `n11/` (`FORM`, `NOCALL`, `SKETCH_PICKS`, `SELECT`, `SELECT_THINKING`, `CARDS`, `SELECT_BOUND`, `INSPECT`, `LIB`, `MODE`, `CUT`, `RULES`, `RESEND`, `FINISHRUN`, `FINISHFAIL`, `DRAFTS`, `PROMPT`), each holding one setting's word, the settings N11 reads at its start (lanes bake1, rebuild1 and cleandefault1; our own choice, no data). `n11/DRAFTS` says `one`: before the loop's first request N11 sends N0's one-shot request once (built by `n0/`'s own code, N0's system prompt, temperature 0 and the seed) and runs the script the House wrote once in a directory of its own; its files are held aside and written to the output at the close only where the loop left nothing to grade. `n11/PROMPT` says `clean`: the loop's system prompt, its first message and the selection call's index are the full prompt with eleven consistency edits (`n11/prompts.py`: a rule said twice said once, the paragraphs reordered, a file's description that repeats the input data's tree left out), every guidance sentence kept; the text is general, the same for every unit. N11 is a loop of native tool calls: the House writes small files under a work directory in `/tmp`, runs them, inspects input files and reads `qf`'s documentation through five commands, each answered by code with a bounded observation of what happened (the run's exit and output, the traceback inside its own files, the output files present, general checks that every output file the instruction names exists, parses and holds finite numbers, the output's own self-report, and the requests and seconds left), until it finishes, the checks pass at a finish, 20 requests are spent or the clock ends. Under 7.5 KB of instruction its first request is N0's, byte for byte. Where `n11/FALLBACK` says `oneshot` (none is committed), the loop holds a reserve of its clock and one request until its output holds a file to grade, and where it stops with nothing to grade it sends N0's one-shot request through `n0/`'s own code and runs the script the House wrote once. The system prompt carries `qf`'s index; where the instruction holds a term a `qf` docstring names as an alias, one line says the library has that function. `qf/` is N9's library as above. `n11/examples.jsonl` (lane example1, built on the desk on 10-16 by `scripts/examples_corpus.py` from the records our error ledger names) holds our own solutions to 56 public units, the open ones the candidate solved on every recorded reading (the kit's `dev` split and the fresh set's `fresh-dev` and `fresh-drafts`; no sealed unit, no holdout unit): each the script the House wrote in one of our recorded runs and that passed that unit's checks, with that unit's id, split and family, its instruction (canary lines out) and its input files' first lines or JSON keys and kinds; no separately bundled data file, check or reference-output file. Where `n11/EXAMPLE` says `nearest` (none is committed) the loop's first message shows one of them as a worked example, the one whose instruction's words overlap this unit's most: rule 8 lets such solutions travel as in-context examples for other units only, so it is never this unit's, by its id (the card's `[task] id`, its stress twin or its source) or by its content (an instruction whose words overlap this one's at 0.95 or more, or whose nonempty set of named output files equals this one's), a match below 0.12 is not shown, and the example is shown, never run or copied. These are conservative recognition heuristics, not proof against a rewritten task with renamed outputs. The builder and cold reviewer judge this use consistent with rule 8; an image carrying the corpus still needs the owner’s interpretation if the switch survives its screen. Beyond choosing that example, N11's prompts and checks are general, the same for every unit; it does not execute a stored solution directly: `write` reaches the work directory alone, so every deliverable is written by a script the House wrote, run in that unit (rules 8 and 9).
- `n3/` (`AGENT=n3`), with `common/` and `model.py` as above: our own code, written for this program. The delivery counts as complete only when every output file the instruction names exists, else the one repair is asked; a cut reply is continued and salvaged as N1's is; its system prompt is N0's with a five-line note on pandas 3's changed API (frequency aliases, `ffill`, `.iloc[0]`, `.loc`, `DataFrame.map`, `ddof`). At most 5 requests a unit. The inspection's wording is general, the same for every unit; N3 holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by the script the House writes in that run (rules 8 and 9).
- `n4/` (`AGENT=n4`), with `common/` and `model.py` as above: our own code, written for this program. - `l1/` (`AGENT=l1`), with `common/` and `model.py` as above: our own code, written for this program. L1 is the loop with fat steps: from the same opening request as N0, each House reply is a contract (the output files the instruction asks for, their keys or columns, types and rounding, and up to five checks the model states from the instruction) and one complete Python script; the script runs, code checks the output against the contract (`common/contract.py`) and runs the model's own checks, and a failure goes back with the latest script for a whole rewrite, at most 12 requests a unit. The checks are the model's, stated from that run's instruction; no finance check, unit id, text, data or answer is ours, and every deliverable is written by the script the House writes in that run (rules 8 and 9).
- `w1/` (`AGENT=w1`), with `common/` and `model.py` as above: our own code, written for this program. W1 asks the House for three scripts at once, each with N0's request under one of three fixed instructions on working style written in the code (N0's own, N1's compact clause, explicit checks of intermediate results; two more, helper functions first and vectorised array work, are written for a form of five), none naming a unit, a task, a file or a library beyond the installed ones. Each script runs in turn; those that exit cleanly and write files are compared by the numbers in their files, and the files of the largest group that agree are copied into the output. Where none runs cleanly, one repair request on the script that got furthest, as N0's. At most 8 requests a unit. It holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by a script the House wrote in that run and ran in that run, and the vote only chooses among them (rules 8 and 9).
- `w2/` (`AGENT=w2`), with `common/` and `model.py` as above: our own code, written for this program. W2 is W1 with one change: each of its three drafts is asked at temperature 0, the model's most likely reply, where W1's are sampled at 0.6; its fixed instructions on working style, its runs, its vote, its repair and its 8-request cap are W1's. It holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by a script the House wrote in that run and ran in that run, and the vote only chooses among them (rules 8 and 9).
- `pi/` (`AGENT=pi`), with `common/`, `qf/` and `model.py` as above (`model.py` unused: pi's requests go through the wrapper's proxy): our own code, written for this program, around pi 1.1.0, an open-source coding agent (`@earendil-works/pi-coding-agent`, MIT, by Mario Zechner; under `/opt/pi`, with Node 22's binary under `/opt/node`). The wrapper reads the mounted unit as N0 does. It starts a proxy on 127.0.0.1 that alone holds the House's credentials, counts every request at admission and refuses past 20, and forces the House limits on each (4,000 output tokens, thinking off, temperature 0, a fixed seed). It then runs pi once on the unit in print mode, offline and with no session, with pi's four tools (read, bash, edit, write) and a system prompt of ours stating N0's rules. pi's own loop asks the House for each step and runs the tool calls the House's replies make: it writes and runs the House's scripts, and those write the deliverables. pi's environment holds none of the House's variables, and the wrapper is undumpable, so no process pi starts reads them from its `/proc` entries. pi and every process it started are killed before the unit's deadline, the output is closed as N0's, and the exit is 0. The wrapper writes no file into the output. It holds no unit's id, text, data or answer and branches on no unit: every deliverable is written by a tool call the House made in that run (rules 8 and 9). `qf/` is under `/opt/agent` as in N9's image, and no prompt of pi's names it.
- `recall/` (`AGENT=recall`): our own code, on the same `common/` and `model.py`. It is a measurement, never an upload: it asks the House, once (a second request only to continue a reply the output cap cut), for the contents of every output file a unit's instruction names, shown the instruction with its canary lines removed and no input file, no digest and no path map, and writes the files the reply gives (JSON parsed and re-serialised) for the unit's checks to score. A pass is the House's recall of the unit's reference values, which is what the probe counts (`runs/lanes/E004-draft.toml`). A unit with no data files is asked nothing. It holds no unit's id, text, data or answer and branches on no unit; every file it writes is the House's reply in that run.
- `ROSTER_CAP`: one number of seconds, `600`, copied in the base stage beside `/opt/agent/model.py`, so every agent's image holds it: our own setting of the client's roster cap (ASK-10's default, lane ship1). The client's deadline is the smaller of it and the card's `[agent] timeout_sec` less the 200 s kept for the platform's start, counted from the process's start (`model.unit_deadline`); the desk's `AGENTHON_MODEL_ROSTER_CAP_S` overrides it, which no platform sets. It holds no unit's id, text or answer.
- `examples/exemplar_agent/` (`__init__.py`, `solve.py`): the kit's exemplar agent, copied unchanged from `vendor/track1-coding-public/examples/exemplar_agent/` (its `harbor_agent.py` is left out: it imports Harbor, which the image does not hold). It is the organisers' code, not ours, and it is a complete solution written in advance for one public unit, `t1-EXAMPLE-bs-greeks-pde`: closed-form Black-Scholes prices and Greeks computed at run time from that unit's `options.parquet`. It refuses any other unit, holds no answer values, and calls no model. Under rule 9 it earns no credit, and under rule 8 a prepared solution may not be used on the unit it solves. So an `exemplar` image is plumbing for the platform's shape and the checker, and it is never uploaded as a run.
